# 1. 这份计划解决什么问题

本项目由多人接力并借助 AI/Codex 开发。为了避免任务重复、接口被多人同时修改、计划文件越勾越乱，后续统一采用：

> **一个版本只解决一个核心问题；一个阶段只交给 AI 一个明确任务；每完成一个版本，立即暂停开发，进行完整测试、人工验收和计划重排。**

这份文件只保留四类内容：

1. 当前项目状态；
2. 当前版本的详细步骤；
3. 后续版本的高层目标；
4. 版本验收、复盘和接力模板。

旧版本的数十条实现细节不再长期保留在主计划中。已完成内容只记录“结果、PR、测试和结论”。

# 2. 团队统一工作循环

每个版本都必须按下面六个阶段运行。

```text
① 版本规划
   ↓
② 分棒开发
   ↓
③ PR 与持续集成
   ↓
④ 真实案例人工验收
   ↓
⑤ 版本冻结与完整测试
   ↓
⑥ 复盘并重写下一版本计划
```

## 2.1 版本规划

开始一个新版本前，团队必须明确：

- 本版本只解决什么问题；
- 本版本明确不做什么；
- 输入和输出对象是什么；
- 需要哪些真实案例和人工标准答案；
- 分成几棒，每棒由谁负责；
- 每棒允许修改哪些文件；
- 本版本最终如何验收。

## 2.2 分棒开发

每一棒必须满足：

- 只包含一个核心任务；
- 先检查仓库、接口和测试；
- 先说明修改范围，再编码；
- 不同时让两个 AI 重写同一模块；
- 不自动提交、推送或创建 PR，除非负责人明确要求；
- 每棒结束后先测试、审查 diff，再进入下一棒。

## 2.3 PR 与持续集成

每一棒至少执行：

```bash
pytest -q
python scripts/validate_project.py
python -m compileall -q app src
git diff --check
```

合并条件：

- 自动测试通过；
- 原有 Mock 模式未被破坏；
- 没有无关改动；
- 人工验收项已完成；
- 完成信息已回填；
- 下一棒输入已经明确。

## 2.4 版本暂停点

一个版本的最后一棒合并后，**停止新增功能**，进入版本暂停点。

暂停期间只允许：

- 修复阻塞 Bug；
- 补充测试；
- 完成真实案例验收；
- 更新文档；
- 独立环境复跑；
- 整理下一版本范围。

## 2.5 版本复盘

每个版本结束后必须回答：

```text
本版本原目标是什么？
实际完成了什么？
哪些指标通过？
哪些功能没有完成？
哪些设计需要保留？
哪些设计需要修改？
出现了哪些错误或返工？
下一版本最重要的唯一目标是什么？
下一版本哪些内容明确不做？
```

## 2.6 重新规划下一版

只有当前版本通过退出门槛后，才展开下一版本的详细任务。

因此：

- 当前版本：写详细步骤；
- 下一个版本：只写候选目标；
- 更远版本：只保留路线图，不提前写大量复选框。

# 3. 团队分工

| 角色 | 主要职责 | 每个版本必须提交的结果 |
|---|---|---|
| 技术负责人 | 拆分 AI/Codex 任务、控制代码主线、审查 PR、发布版本 | 代码、测试、PR、版本说明 |
| 技术备份 | 在独立环境安装、运行、测试并记录问题 | 独立测试记录、Bug Issue |
| 财务/业务标注 | 制作人工标准答案，核对财务和业务风险 | 数值、单位、期间、页码、原文 |
| 法务/第二复核 | 法务标注和人工标准答案二次复核 | 复核记录、分歧记录 |
| 产品与材料 | 页面验收、案例包装、报告、PPT和演示 | 截图、操作说明、案例材料 |

## 团队红线

- 正式代码主线由技术负责人统一控制；
- 不让多个 AI 同时修改同一核心模块；
- 所有数值必须能追溯到 Evidence；
- 所有精确计算必须由 Skill 完成；
- 不提交 Token、密码、API Key、`.env`；
- 不把本地绝对路径写死；
- 不删除 Mock 实现；
- 不通过放松测试断言来“修复”测试；
- 不把规则风险分数宣传为真实概率；
- 大型真实 PDF 默认只保存在 `data/local/`，并由 `.gitignore` 排除；
- 真实 PDF 是否可以进入仓库，必须单独完成版权、体积和授权审查，不能在计划文件中默认视为已提交；本案例 `real_case_001/prospectus.pdf` 是经负责人明确授权后通过 PR #12 提交的例外。

## 第 4 棒：现金跑道 Calculation 与 RiskItem

**状态：等待第 3 棒。**

### 输入

- 归一化现金；
- 归一化经营现金流；
- 对应 Evidence。

### 唯一任务

通过确定性 Skill 计算现金跑道，并生成：

- `Calculation`
- `FIN_CASH_RUNWAY RiskItem`

### 计算原则

```text
年度现金消耗 = max(-经营现金流年化值, 0)
现金跑道（月） = 现金 / 年度现金消耗 × 12
```

对于三个月现金流：

```text
年度现金消耗 = 三个月现金消耗 × 4
```

当前人工参考值：

```text
三个月现金消耗：83,918 千元
年化现金消耗：335,672 千元
现金：77,208 千元
现金跑道约：2.76 个月
```

### 不能计算的情况

- 缺现金；
- 缺经营现金流；
- 单位未知；
- 币种不一致；
- 期间未知；
- 经营现金流为正；
- 分母为 0。

### 合并条件

- Calculation 记录输入、公式、过程、结果和 Evidence；
- Agent 不重复写公式；
- RiskItem 初始状态不是 verified；
- 系统结果与人工计算一致；
- 异常条件均有测试。
