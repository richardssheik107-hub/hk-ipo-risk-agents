# v0.2.0 版本复盘

## 版本目标

验证v0.1.0的模块边界能否在不推翻架构的情况下，将Mock文档链路替换为一条真实、可核验的港股IPO招股书风险闭环。

## 已实现

- PyMuPDF按物理页解析真实招股书，保留稳定Chunk和原文；
- 关键词Retriever定位正式现金流量表，并经过24份影子样本和定向整改；
- 确定性提取现金、经营现金流、币种、单位和期间；
- CashRunway Skill生成Calculation，RiskItem引用真实Evidence；
- 专用Verifier核验Evidence和Calculation，Predictor只消费verified风险；
- Service级真实E2E、Streamlit证据链展示和结构化故障降级；
- 565份招股书manifest、行情覆盖及官方IPO主数据桥接。

## 做得好的地方

- 影子测试在进入财务抽取前暴露了Retriever泛化不足，避免把单案例成功误判为可用；
- Mock与真实实现沿用同一公共接口，Service和Workflow无需重构；
- 规则分、概率和市场数据缺失的语义被明确区分；
- 真实数字风险同时具备Evidence和Calculation，可回到PDF物理页复核；
- 故障场景保留partial结果，不因单节点异常丢失已完成分析。

## 暴露的问题

- 正式报表定位不能只依赖单个关键词，需要标题邻域、章节、表格密度和负面上下文共同打分；
- PDF文本抽取仍依赖可复制文本，扫描件和复杂表格尚未覆盖；
- 单一现金跑道无法代表多Agent完整分析能力；
- 市场数据和上市后标签口径尚未冻结，当前规则分不能解释为概率；
- 团队独立复跑应更早制度化，并保存环境、提交SHA和验收命令。

## 对v0.3.0的输入

1. 保留v0.2现金跑道黄金回归与Mock端到端测试；
2. 先建立5—10份黄金案例和统一标注规范，再扩展风险；
3. 依次实现Financial、Legal、Business真实Agent及专用Verifier；
4. 扩展Retriever查询族，但不改变公共返回Schema；
5. 保持无API Key确定性链路可运行；
6. 市场标签、Market Agent和统计预测模型继续留到v0.4；
7. v0.3发布前重复独立克隆安装、真实E2E和界面故障降级验收。
