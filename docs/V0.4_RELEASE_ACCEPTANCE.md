> Snapshot: 2026-08-25  
> Release identity: `v0.4.0`  
> Scope: **Competition Preview / integration milestone**  
> Competition end state remains: `v0.4.5 COMPETITION_READY`

## 1. Why v0.4.0 can ship before v0.4.5

`v0.4.0` freezes the current major integration milestone without pretending the
competition submission is complete. The repository already contains materially
new v0.4 capabilities beyond v0.3: governed Market-X context, four-channel Final
Supervisor composition, real remote-LLM provider support for Legal/Business,
competition runtime contracts/trace sidecars, improved table/financial extraction,
and Market Intelligence Skills/Agent implementation.

The remaining work is competition hardening and final product closure. It is kept
visible as a separate `v0.4.5 COMPETITION_READY` gate rather than delaying the
major-version checkpoint or hiding incomplete channels.

## 3. What is intentionally not a v0.4.0 blocker

These items are important for final competition submission but do not prevent an
honest v0.4.0 milestone release:

- original frozen PR-F per-case runtime/handoff;
- industry return, still `INDUSTRY_MAPPING_PIT_BLOCKED`;
- `ComparableIPOSkill`, still deferred without a formal PIT-safe definition;
- broad model tuning / new model families;
- full 438-case LLM execution;
- perfect Financial extraction coverage.

If PR-F is absent, the model channel must remain explicitly unavailable. No
retraining, reconstruction, score inversion or fabricated signal is allowed.

## 4. Current competition blockers for v0.4.5

### Closed A blocker — Market Intelligence formal runtime wiring

The AI configs now use:

```yaml
market_agent: market_intelligence
market_context: governed_pr_b_core
```

The normal Streamlit / `IPOAnalysisService` path therefore runs:

```text
governed MarketContext
→ IPOHeatSkill / MarketRegimeSkill
→ MarketIntelligenceAgent
→ bounded LLM interpretation when provider is available
→ TraceEvent / AgentResultEnvelope diagnostics
→ enriched MarketContext
→ Final Supervisor input
```

The integration does not move Market Intelligence into the legacy Agent loop,
because that loop has a different input contract. Offline v0.4 configs remain
`market_agent: disabled`, preserving the deterministic baseline. If the LLM is
unavailable, deterministic governed Market Intelligence remains available with an
explicit unavailable interpretation status.

### Blocker B — Final Supervisor is still deterministic composition

`V04FinalSupervisor` preserves channels/conflicts and reports uncertainty, but it
explicitly does not arbitrate conflicts. Competition close requires:

```text
Agent disagreement
→ Conflict
→ one controlled targeted re-check
→ Verifier challenge
→ LLM Final Supervisor resolution / unresolved status
```

No unlimited autonomous loop is required.

### Blocker C — multi-horizon outcome/evaluation package is incomplete

The final package still needs reproducible:

```text
return_1d
return_5d
return_20d
return_60d
```

plus submission artifacts such as:

```text
test_predictions.csv
multi_horizon_results.csv
evaluation_summary.json
ai_vs_offline_report.json
```

The frozen 5D outcome must not be silently rewritten.

### Blocker D — final real-case matrix is not yet closed

Competition-ready requires at least 3 stable real IPO E2E cases, ideally 3–5,
covering Document semantics, Market context, and at least one controlled conflict /
re-check path. One successful case is not enough for the final gate.

### Blocker E — competition metrics/artifacts are not yet closed

Required final evidence:

```text
Risk extraction accuracy target >= 80%
Evidence Recall target          >= 85%
Agent / Tool / Evidence trace   = 100%
```

The repository also needs a submission-ready Risk/Evidence benchmark, reasoning
logs, case reports, Evidence Viewer/Human Review outputs, and reproducible runbook.

### Blocker F — Document LLM quality still needs real-case re-test

The remote provider path is live and PR #124 hardened Legal structured validation
and Business semantic reconciliation. The same real case must be re-run after
that fix so the result is measured rather than assumed. Genuine semantic
conflicts remain fail-closed.

### Formal PR-H runtime blocker — frozen model handoff and real-case assets

The historical PR-H frozen manifest remains authoritative for its formal freeze:
without the original frozen PR-F runtime/sanitized handoff and the minimum real
prospectus case matrix, PR-H cannot be relabeled `COMPLETE / FROZEN`. Competition
product work can continue with the Model channel explicitly unavailable.

## 5. Fastest path from v0.4.0 to competition-ready

Do not expand scope. Close only these lanes in parallel:

```text
A  integration + CI + real-case matrix + release/submission closure
B  post-fix Legal/Business real-case benchmark
C  Market Intelligence quality/readiness only; runtime wiring is now closed
D  1D/5D/20D/60D + final evaluation artifacts
E  LLM Final Supervisor + one conflict/re-check + Trace/Human Review
```

Merge only small, contract-compatible PRs. No broad refactor, no new model family,
no industry-PIT research, and no UI-only feature that lacks backend truth.
