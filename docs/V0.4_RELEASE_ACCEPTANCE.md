This run closed the Market missingness crash and exposed three smaller closure defects.

### 4.1 Final Supervisor transport resilience

The remote `openai_responses` Final Supervisor failed with:

```text
LLMProviderError: LLM transport request failed
```

With a 60-second provider timeout and two normal transport retries, the final remote node could wait for three failed transport attempts after the rest of the E2E run had already completed.

Current hardening keeps the same model, credentials, bounded payload and Pydantic schema, but for **`final_supervision_synthesis` only** it now uses:

```text
one Responses transport attempt
→ if and only if the failure is recoverable transport
→ same client + same model through Chat Completions JSON
→ same caller-owned Pydantic validation
→ same scope validation in LLMFinalSupervisor
→ otherwise deterministic fail-closed fallback
```

The fallback is explicitly traced as `openai_responses_chat_fallback`; it is not presented as a successful Responses function call. Authentication/request/schema failures do not trigger this transport fallback. Legal, Business and Market provider policy is unchanged.

This closes the code-level latency/fallback defect, but a **real 2410.HK rerun is still required** before remote Final Supervisor is accepted as PASS.

### 4.2 Market trace Evidence accounting

The three unaccounted trace events matched the three Market Intelligence events: `IPOHeatSkill`, `MarketRegimeSkill`, and Market LLM interpretation. They reason over governed Market-X facts rather than prospectus Evidence, but the trace previously carried neither their namespaced market Evidence IDs nor an explicit no-Evidence reason.

Current hardening now attaches:

```text
market_feature:<feature_id>
market_skill:deterministic_context
```

to the Market trace events. These are existing governed channel references, not fabricated prospectus Evidence. `traceability_report` already treats namespaced non-document references separately from prospectus Evidence resolution, so `92/92` document Evidence semantics are not diluted.

The regression target is that every Market Intelligence event has Evidence, Calculation, or an explicit `no_evidence_reason`. The expected 2410 effect is `22/25 → 25/25`, but that value remains **RE-RUN REQUIRED**, not pre-declared.

### 4.3 UI summary semantics

The top card previously labelled the frozen Document Supervisor string as `Final Supervisor 综合结论`. For 2410 this displayed `0 unresolved conflict(s)` even though the Competition conflict layer correctly held `2 partially_resolved + 3 unresolved`.

The UI now keeps the layers separate:

```text
LLM available
→ show LLM Final Supervisor judgement

LLM unavailable
→ label the old text as 确定性 Document Supervisor 汇总
→ show the LLM unavailable reason explicitly

always
→ show Competition Conflict resolved / partially_resolved / unresolved counts separately
```

The UI does not recompute conflict state; it only projects existing `component_diagnostics`.

## 5. Core-only vs Extended Market runtime

Default settings keep `market_extended_readiness` empty. Therefore the competition runtime is allowed to operate as:

```text
Market-X Core available
+ recent IPO context available
+ Extended HSI / turnover / volatility absent
→ IPO Heat may still be available
→ Market Regime may be INSUFFICIENT_DATA
→ Market Intelligence remains a valid deterministic partial result
```

If a governed local Extended readiness artifact is available, it may be supplied through config or `IPO_RISK_MARKET_EXTENDED_READINESS`. Missing industry returns remain `INDUSTRY_MAPPING_PIT_BLOCKED` unless a legitimate historically effective mapping exists.
